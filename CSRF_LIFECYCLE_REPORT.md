## What Changed

### Backend (`handlers.go`)

`validateCSRF()` no longer deletes the token after use. Token is validated by expiry timestamp only, cleaned up by `cleanupSessions()` goroutine every 5 minutes.

```go
// BEFORE (single-use — token consumed on first request):
func validateCSRF(token string) bool {
    csrfTokens.RLock()
    expiry, exists := csrfTokens.data[token]
    csrfTokens.RUnlock()
    if !exists || time.Now().After(expiry) {
        return false
    }
    csrfTokens.Lock()
    delete(csrfTokens.data, token)  // ← REMOVED
    csrfTokens.Unlock()
    return true
}

// AFTER (session-level — token reusable within 30-minute window):
func validateCSRF(token string) bool {
    csrfTokens.RLock()
    expiry, exists := csrfTokens.data[token]
    csrfTokens.RUnlock()
    if !exists || time.Now().After(expiry) {
        return false
    }
    // Token is session-level — do NOT delete after use
    // Token expires via expiry timestamp, cleaned up by cleanupSessions()
    return true
}
```

## Token Lifecycle Design

```
1. User logs in
2. Frontend fetches GET /api/csrf-token → gets token (valid 30 minutes)
3. Token stored in JavaScript memory (not localStorage)
4. All POST/PUT/DELETE requests include X-CSRF-Token header
5. Server validates token exists + not expired → allows request
6. Token is NOT consumed — can be reused for entire session
7. After 30 minutes, token expires → frontend must re-fetch
8. On logout, frontend clears token from memory
```

**Security properties:**
- Token is single-origin (generated server-side, tied to session)
- Token expires after 30 minutes (configurable)
- Token is never stored in localStorage/cookies (XSS-resistant)
- Token is never logged or transmitted in URLs
- Old tokens cleaned up by background goroutine
